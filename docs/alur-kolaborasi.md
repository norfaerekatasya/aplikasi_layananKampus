# Alur Kolaborasi DevOps

## Skenario
QA menemukan bahwa halaman portal belum memiliki informasi yang jelas mengenai layanan akademik. Temuan dicatat sebagai Issue. Developer kemudian memperbarui konten halaman pada branch fitur. Perubahan diajukan melalui Pull Request dan diperiksa sebelum digabungkan.

## Tahapan
1. QA membuat Issue berisi masalah, langkah pemeriksaan, dan hasil yang diharapkan.
2. Developer membuat branch berdasarkan Issue.
3. Developer melakukan perubahan dan commit.
4. Developer membuka Pull Request menuju branch main.
5. GitHub Actions menjalankan pemeriksaan otomatis.
6. Reviewer memeriksa perubahan dan memberikan persetujuan.
7. Perubahan digabungkan setelah seluruh pemeriksaan lulus.
8. Operations memeriksa hasil rilis dan memantau aplikasi.

## Catatan simulasi
Repository ini merupakan demonstrasi akademik. Aktivitas dan peran dijelaskan secara transparan; jangan menganggap simulasi sebagai bukti bahwa beberapa orang sungguhan telah berkolaborasi.
